# UI接口设定
**无论哪种平台,本质上都是对统一的数据数据流进行显示,皆采用MVVM架构的思想来实现**

## 数据流定义
**UI显示对数据流进行了抽象,可以很方便地兼容SPI,串口,BLE等通信协议**
### 速率
分析所需数据:
- ADC实时采样数据: 每个采样点`16bit`
- 幅值,频率,周期,THD等,都是float数据,每个`32bit`
- 其他控制信号,认为最大为`16bit`

由于波形参数都是较大的float,且对实时性要求不高,定为每500周期发送一次. 我们为波形参数预留16个位置,采用主动发送变化的部分.
规定控制信号在每个数据发送周期只能传输一个

综上,可以计算出最大带宽(每周期): 
$$
\lfloor 16+16+ \frac{32*16}{500} \rfloor = 34
$$
就以通信的最低要求`9600bps`的串口来说,最坏情况下有280个周期,即3ms更新一次,还不错.

为了兼容性,我们一开始以`9600bps`速率发送数据,与上位机协商得到最终速率(也可以考虑不同发送方式直接用不同的速率,但是我不喜欢硬编码)


## 相关数据帧定义
### 实时上报数据
`帧头`: 固定值**0b_0110_1011**

接下来数据按照如下次序依次出现:
|   名称    |   类型    |   位数|   说明    |
|   ----    |   ----    |   ----    |   ----    |
|   wave    | 整数数组  |   16n     | 波形各处的电压  |
|   freq    |   实数    |   32      |   频率    |
|   period  |   实数    |   32      |   周期    |
|   duty    |   实数    |   32      |   占空比  |
|   amp     |   实数    |   32      |   幅值    |
### 测试相关数据
#### 上报时
`帧头`: 固定值**0b_1100_1010**\
`...测试项目`:
- `项目`:7位枚举值
- `状态`: 1位布尔值,1表示通过

#### 下发时
`帧头`: 固定值**0b_1100_1011**

`...测试项目`:
- `项目`:8位枚举值
- `容差`:8位无符号,表示容差百分比
- `目标值`:与上报数据类型相同

可用项目如下:
|枚举值|   项目    |
| ---- |   ----    |
| 1 | freq |
| 2 | period |
| 3 | duty |
| 4 | amp |

### 设定相关数据
上位机和fpga采用通用的格式:

`帧头`:固定值**0b_1111_0100**\
`项目`:8位枚举值\
`值`: 16位整型

| 枚举 | 项目 | 类型 | 说明 |
| ---  | ---  | ---  | ---  |
|  1   | baud | u16  | 波特率,单位bps|
|  2   | frame_rate | u16  | 帧率 |
